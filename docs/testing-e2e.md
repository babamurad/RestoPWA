# Сквозные тесты в браузере (Laravel Dusk)

Эти тесты открывают настоящее приложение в Chrome и делают то, что делает человек: ищут блюдо, выбирают добавки, оформляют заказ, входят курьером, отклоняют заказ в панели ресторана. Они ловят то, чего не видят тесты PHPUnit и Vitest: ошибки в склейке экрана и сервера.

Тесты лежат в `tests/Browser`. Они запускаются в CI отдельным заданием **E2E (Dusk)** на каждый pull request.

## Что покрыто

| Набор | Сценарии |
|---|---|
| `CatalogTest` | список ресторанов, поиск по названию блюда (в том числе кириллицей), фильтр по кухне, смена языка (и что он сохраняется), пустая корзина |
| `OrderingTest` | обязательная добавка и лимит «до N» в карточке блюда, цена на кнопке, две строки корзины для одного блюда с разным выбором, гость отправляется на вход и возвращается к оформлению, **полный заказ с самовывозом и отмена клиентом**, нельзя отменить заказ, который уже готовится, смена ресторана в корзине |
| `CourierFlowTest` | курьер выходит на смену, берёт заказ (до этого не видит данных клиента), не может закончить смену с заказом в пути, доставляет; клиенту экран курьера недоступен |
| `PanelsTest` | доска заказов ресторана (новый заказ выделен), отклонение заказа с причиной, вход в панель, аналитика администратора и закрытый доступ для ресторатора |
| `TrackingAndProfileTest` | страница отслеживания по подписанной ссылке (подделка — 403), чужой заказ, настройки оповещений в профиле |

Группа `smoke` — быстрая проверка главного, `merge-gate` — то, без чего нельзя сливать:

```bash
php artisan dusk --group=smoke
```

### Чего тесты не проверяют

- **Доставку с выбором точки на карте.** Карта — внешний сервис (Яндекс), поэтому заказ в тестах оформляется самовывозом. Зона доставки и цена по районам покрыты тестами PHPUnit.
- **Реальное время (Reverb) и push.** Экраны проверяются в режиме опроса, как при выключенном websocket.
- **Мобильное приложение (Capacitor).**

Тесты не ходят в интернет: Chrome запускается с `--host-resolver-rules`, который закрывает все адреса, кроме локального. Шрифты, стоковые картинки и карта в тестах не грузятся.

## Как запустить у себя

Нужны Chrome (или Chromium) и PHP с SQLite. Приложение должно работать на отдельной базе и со **сборкой** фронтенда: тесты идут по сети, как браузер человека.

1. Один раз подготовить базу и собрать фронтенд (повторять после изменений в `resources/js`):

   ```bash
   touch database/dusk.sqlite
   ```

   ```bash
   npm run build
   ```

2. Скачать ChromeDriver под установленный Chrome:

   ```bash
   php artisan dusk:chrome-driver --detect
   ```

3. В отдельном окне запустить приложение в окружении `.env.dusk.local` (оно использует `database/dusk.sqlite`, почту в памяти, очередь без фона):

   ```bash
   php artisan serve --host=127.0.0.1 --port=8001 --env=dusk.local
   ```

4. Запустить тесты:

   ```bash
   php artisan dusk
   ```

   Один набор или один тест: `php artisan dusk --filter=OrderingTest`.

Перед каждым тестом таблицы очищаются (`DatabaseTruncation`), а Chrome запускается заново, поэтому тесты не зависят друг от друга: ни выбранный язык, ни вход, ни корзина из прошлого теста не остаются.

### Переменные окружения

| Переменная | Для чего |
|---|---|
| `DUSK_CHROMEDRIVER_PATH` | свой ChromeDriver (версия должна совпадать с Chrome) |
| `DUSK_CHROME_BINARY` | свой Chrome, не системный |
| `DUSK_NO_SANDBOX=1` | нужен, если Chrome запускается от root или в контейнере (в CI включён) |
| `DUSK_HEADLESS_DISABLED=true` | показать окно браузера и смотреть тест глазами |

## Если тест упал

- Скриншот упавшего теста — `tests/Browser/screenshots`, лог консоли браузера — `tests/Browser/console`. В CI они прикладываются к заданию как артефакт `dusk-failure` вместе с логом сервера.
- Лог приложения — `storage/logs/laravel.log`, лог сервера — окно, где запущен `artisan serve`.

## Как писать тесты

- **Селекторы — атрибут `dusk`.** В шаблонах Vue элементы, которые нужны тестам, помечены `dusk="..."` (например `dusk="add-to-cart"`, `:dusk="'product-' + product.id"`). В тесте это `@add-to-cart`. Не привязывайтесь к классам Tailwind и к тексту, который переводится.
- **Текст может быть другим на экране.** Заголовки с `uppercase` Chrome отдаёт заглавными буквами: `assertSee('Что вам присылают')` не найдёт «ЧТО ВАМ ПРИСЫЛАЮТ». Ищите по `dusk`-атрибуту или `aria-label`.
- **Ждите, а не спите.** После перехода и после запроса к серверу используйте `waitFor`, `waitForText`, `waitUntilMissing`, `waitUntilEnabled`. Страницы приложения подгружаются лениво, поэтому поле сразу после `waitForLocation` ещё может отсутствовать. `pause()` — только если нет ничего, чего можно дождаться.
- **Данные — через фабрики и `Concerns/BuildsRestaurants`**, вход — через форму (`UsesTheApp::signIn`) там, где важен сам вход, и через `loginAs()` там, где нет.
- **Проверяйте итог в базе**, не только на экране: заказ создан с нужной суммой и добавками, статус и причина отмены записаны.

## Ловушки, на которые уже наступили

- Dusk держит один браузер на весь класс. Здесь он закрывается после каждого теста (`DuskTestCase::tearDown`).
- После входа Chrome предлагает сохранить пароль, и всплывающее окно отнимает фокус: следующие клики уходят в никуда. Менеджер паролей отключён в `DuskTestCase::driver()`.
- SQLite умеет приводить к нижнему регистру только латиницу, поэтому поиск «плов» не находил «Плов». Поиск по ресторанам подключает SQLite функцию `lower` с поддержкой Юникода (в PostgreSQL на проде такой проблемы нет).
